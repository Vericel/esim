ff 0.1 · Python 3.9+
文档日期 2026-08-02

ff 0.1 · 中文用户指南

Filelist，
展平之后更清楚。

从一份顶层 Verilog/SystemVerilog filelist 出发，处理条件分支、 嵌套引用、环境变量和路径，生成可查阅、可调试的绝对路径 flat filelist。

输入：顶层 filelist 输出：UTF-8 + LF 纯文本 平台：Linux / POSIX

01 · Overview

了解 ff

ff 是 filelist 预处理工具。它把分散在多层 filelist 中的有效条目按原顺序 展开，并将自己识别的路径规范化为绝对路径。

处理什么

条件指令、-f/-F 嵌套、环境变量、注释以及已识别的路径选项。

产生什么

一份语义等价的纯文本 flat filelist，作为权威持久化产物。

不处理什么

第一版不考虑 mixed-language 或 logical library，也不生成 JSON、依赖文件或 source map。

一个重要边界：ff 只预处理 Verilog/SystemVerilog flat filelist，不替代仿真器解析其他选项。

02 · Install

从离线 wheelhouse 安装

ff 需要 Python 3.9 或更高版本。在目标 EDA 机器上，建议使用准备好的本地 wheelhouse， 安装过程不访问网络。 

python3 -m pip install \
  --no-index \
  --find-links ./wheelhouse \
  esim==0.1.0

wheelhouse 需包含

  • esim 0.1.0 wheel
  • botticelle-onelog 0.1.x wheel
  • Rich wheel
  • Rich 的传递依赖 wheel

安装后检查 CLI 是否可用：

ff --help

03 · Quick start

第一次展平

给 ff 一份顶层 filelist。如果不指定 -o，它会在当前工作目录生成 ./flattened.f。

示例：默认输出

输入 · /proj/tb/top.f 
../rtl/top.sv
+incdir+../rtl/include
命令 
cd /proj/tb/run
ff /proj/tb/top.f
结果 · /proj/tb/run/flattened.f 
/proj/rtl/top.sv
+incdir+/proj/rtl/include

指定输出和宏

ff /proj/tb/testbench.f -o testbench.f -d MACRO_1 MACRO_2

相对输出 testbench.f 以当前工作目录为基准。MACRO_1 和 MACRO_2 作为“已定义”标记，用来选择条件分支。

04 · Command line

CLI 参数

ff 的命令格式是 ff INPUT [OPTIONS]。INPUT 必须是第一个参数。

CLI 选项
参数是否必需行为
INPUT是顶层 filelist，必须位于所有选项之前。
-o, --output否输出路径；默认为当前目录的 ./flattened.f。
-d, --define否一次接收一个或多个无值宏，可重复指定。
-l, --log否启用日志；不带路径时写 ./ff.log，也可紧跟自定义路径。
--debug否将 DEBUG/trace 信息打印到终端；与 -l 同用时也写入日志。

输出路径

  • 显式的相对输出路径以 ff 启动时的当前工作目录为基准。
  • 输出父目录必须已存在；ff 不自动创建目录。

预定义宏

ff top.f -d FPGA USE_DDR
ff top.f -d FPGA -d USE_DDR
ff top.f --define FPGA --define USE_DDR
  • 所有 -d/--define 值合并为集合，重复宏去重，名字区分大小写。
  • 宏名匹配 [A-Za-z_][A-Za-z0-9_$]*。
  • 只支持无值的“已定义/未定义”标记，不支持 WIDTH=32，也不用逗号分隔。
  • filelist 中的 +define+ 是仿真器选项，ff 原样透传，不会改变宏集合。

退出码

进程退出状态
退出码含义建议
0成功继续使用展平后的 filelist。
1filelist 处理失败根据 source chain 和修复建议修正输入。
2CLI 用法错误检查 INPUT 顺序和选项参数。
3ff 内部程序错误保留日志和重现条件，交给工具维护者。

05 · Conditions

条件指令

ff 根据 -d/--define 传入的宏选择活动分支。支持任意层级嵌套， 但只做条件筛选，不执行宏文本替换。 

`ifdef MACRO
`ifndef MACRO
`elsif MACRO
`else
`endif

示例：选中 MACRO_1 分支

输入 · /proj/tb/top.f 
`ifdef MACRO_1
../rtl/fast_top.sv
`elsif MACRO_2
../rtl/safe_top.sv
`else
../rtl/default_top.sv
`endif
命令 
ff /proj/tb/top.f -d MACRO_1
结果 
/proj/rtl/fast_top.sv

指令语法

  • 指令必须是行内第一个非空白内容，指令名和宏名都区分大小写。
  • 允许尾部注释；去除注释后不得出现多余 token。
  • 条件指令自身和它的尾注释不写入输出。
  • 未知反引号指令一律报错，不会当作仿真器选项透传。

未选中分支

未选中分支仍会检查条件嵌套是否合法，但不展开环境变量、不读取子 filelist、 不验证其他内容或路径，其中的注释也不保留。

缺少或多余宏名、无匹配的 `else/`elsif/`endif、重复 `else、`else 后出现 `elsif，以及 EOF 时未闭合，都是错误。

06 · Nested filelists

嵌套 filelist 与路径基准

-f 和 -F 都会递归展开子 filelist，输出中不再保留引用行。 两者的关键差异是相对路径的基准目录。

相对路径基准
场景子 filelist 路径基准子 filelist 内容基准
顶层 filelist由 CLI INPUT 定位顶层 filelist 的逻辑所在目录（-F 式）
-f child.fff 启动时的当前工作目录同一当前工作目录
-F child.f当前 filelist 的逻辑所在目录被引用 filelist 的逻辑所在目录

示例：-F 跟随当前 filelist

输入 
# /proj/tb/top.f
-F blocks/core.f

# /proj/tb/blocks/core.f
../../rtl/core.sv
命令 
cd /proj/tb/run
ff /proj/tb/top.f
结果 
/proj/rtl/core.sv

循环与重复

  • ff 使用当前引用栈检测递归循环，真实路径身份相同的循环会失败。
  • 同一 filelist 在不同分支或位置被多次引用不等于循环，每次都按位置展开。
  • 普通源码和 -v library file 分别按 symlink 解析后的物理路径去重；一个文件同时作为普通源码和 -v 条目时，两者都保留活动。
  • 首次条目保留原逻辑路径和顺序；后续重复条目会转换为注释，注明首次与重复的 filelist:line，不会静默消失。
  • 重复条目仍会先完成路径展开、存在性、类型和可读性校验；无效的第二次引用不会被去重逻辑掩盖。
  • -y、+incdir+、透传选项、注释和空行保留原顺序与重复。
  • 启用 DEBUG 时，ff 还会记录重复类型、物理路径、两个来源位置和规范化条目。
  • -f/-F 行的尾部注释会提升为展开内容之前的独立注释。

示例：重复物理源文件保留为可追溯注释

输入 
rtl/top.sv
rtl/current/top.sv
结果 
/proj/rtl/top.sv
// ff: duplicate physical source; first: /proj/top.f:1; duplicate: /proj/top.f:2
// /proj/rtl/current/top.sv

上例假定 rtl/current/top.sv 是指向 rtl/top.sv 的 symlink。

07 · Environment

环境变量展开

路径中可使用 $NAME 或 ${NAME}。两种写法语义相同；花括号写法 用于在变量名后紧接其他字符时明确边界。

示例：同一条目展开多个变量

输入 
$PROJ_DIR/rtl/top.sv
+incdir+${DV_HOME}/include
命令 
export PROJ_DIR=/proj
export DV_HOME=/proj/tb
ff /proj/tb/top.f
结果 
/proj/rtl/top.sv
+incdir+/proj/tb/include

展开规则

  • 变量名匹配 [A-Za-z_][A-Za-z0-9_]*。
  • 支持同一路径中的多个变量，也支持变量值中继续引用变量，直到完全展开。
  • 用于普通源码、-f/-F、-v/-y 和 +incdir+ 路径。
  • 展开后仍是相对路径时，沿用该 logical entry 原本的路径基准。

任一层变量缺失、值为空或出现循环引用都会失败。错误会同时展示 source chain 和 environment expansion chain。

不支持 shell 扩展：${NAME:-default}、$(command)、反引号命令、~ 和 ~user 都会被拒绝。

08 · Entries

注释、路径与透传选项

filelist 以“一个物理行对应一个 logical entry”为基本约束。普通源码行只能包含 一个路径，所有路径都不得包含空格或制表符。

注释

  • 支持 // 行注释和不可嵌套的 /* ... */ 块注释。
  • 尾部注释前必须至少有一个空白字符；路径 token 中的 // 不是注释。
  • 块注释可跨行，但必须在同一 filelist 内闭合，不跨 -f/-F 边界。
  • 活动分支的原始注释和空行保留；非活动分支的注释删除。
  • 普通路径条目的尾部注释保留在规范化路径后。
  • -f/-F 的尾部注释提升为展开内容前的独立注释。
  • 多目录 +incdir+ 的尾部注释提升为拆分组之前的独立注释。
  • ff 仅主动增加 symlink target annotation 和 duplicate file annotation。

可识别路径条目

普通非选项 token 都是源码路径，ff 不使用文件扩展名白名单。

ff 会绝对化并验证的条目
形式参数输出行为
source/path任意非选项 token必须是可读普通文件，输出绝对路径。
-f child.f单个分离参数按 CWD 基准递归展开，引用行消失。
-F child.f单个分离参数按当前 filelist 基准递归展开，引用行消失。
-v library.v单个分离参数文件必须存在且可读，保留 -v 并绝对化路径。
-y library_dir单个分离参数目录必须存在，保留 -y 并绝对化路径。
+incdir+dir1+dir2一个或多个非空目录每个目录拆成独立行，保留顺序和重复项。

示例：拆分多目录 +incdir+

输入 
+incdir+../rtl/include+../tb/include  // common headers
结果 
// common headers
+incdir+/proj/rtl/include
+incdir+/proj/tb/include

透传与拒绝

其他仿真器选项原样透传。“未知”不等于“非法”，ff 不猜测透传选项中可能隐含的路径。

不支持反斜杠续行、引号包裹的含空白路径、*/?/[...] glob、紧凑或等号形式的 -f/-F/-v/-y、Windows 盘符和 UNC 路径。/mnt/c/... 是合法 POSIX 路径。

09 · Output safety

路径规范化与安全输出

ff 在展平、校验和渲染全部成功后才发布输出。任何失败都不会留下半成品， 原有输出保持不变。

逻辑路径与真实身份

  • 已识别路径消除 .、.. 和重复分隔符，并输出绝对路径。
  • 输出保留 symlink 的逻辑路径，不用物理路径取代仿真器看到的 token。
  • 存在性、循环和输入/输出冲突检查使用 symlink 解析后的真实文件身份。
  • 经过 symlink 的条目前会增加 symlink target 注释，写明最终物理路径。
  • 损坏 symlink 按“路径不存在”报错；未选中分支中的路径不验证。

示例：保留 symlink 逻辑路径

输入 
/proj/rtl/current/top.sv
# current -> /releases/rtl-42
结果 
// symlink target: /releases/rtl-42/top.sv
/proj/rtl/current/top.sv

文件和目录校验

  • 顶层/子 filelist、普通源码和 -v 参数必须是可读普通文件。
  • +incdir+ 和 -y 参数必须是已存在目录。
  • 输出不得与顶层或任一子 filelist 指向同一真实文件。

编码和原子替换

  • 输入必须是 UTF-8，允许 UTF-8 BOM，接受 LF 或 CRLF。
  • 输出固定为无 BOM 的 UTF-8 + LF，文件末尾保留一个换行。
  • 输出先写同目录临时文件，全部成功后再原子替换目标。
  • 成功时总是替换旧输出，即使内容不变也不保留旧 inode/mtime。
  • 输出目标是 symlink 时，替换 symlink 节点为普通文件，不修改 symlink target。

权限与并发

  • 替换已有普通文件时，保留读写权限但清除可执行位。
  • 新文件权限是 0666 & ~umask。
  • ff 不实现输出进程锁；同路径并发写入时，最后完成的成功调用获胜。
  • 筛选后没有源码路径仍可成功；DEBUG 可提示零源码条目。

10 · Diagnostics

日志与错误排查

默认保持安静；需要留存失败现场时启用 -l，需要看到递归读取和路径解析过程时 增加 --debug。onelog summary 始终关闭。

日志组合
命令形式终端日志文件
ff top.fWARNING / ERROR不生成
ff top.f -lWARNING / ERROR./ff.log，记录 WARNING / ERROR
ff top.f -l ./my.logWARNING / ERROR./my.log，记录 WARNING / ERROR
ff top.f --debugINFO / WARNING / ERROR / DEBUG trace不生成
ff top.f --debug -l完整 DEBUG 级别./ff.log，与终端同等级

示例：记录递归 trace

输入 
/proj/tb/top.f
└─ -F blocks/core.f
   └─ ../../rtl/core.sv
命令 
ff /proj/tb/top.f --debug -l /proj/tb/run/ff.log
结果 
DEBUG reading filelist: /proj/tb/top.f
DEBUG reading filelist: /proj/tb/blocks/core.f
DEBUG resolved source: /proj/tb/blocks/core.f:1 -> /proj/rtl/core.sv
INFO  flattened output: /proj/tb/run/flattened.f

日志文件安全

  • 每次 invocation 覆盖旧日志，不追加。
  • 日志先写同目录临时文件，在成功或可控失败时都发布到目标。
  • 日志不得与输出或任一输入 filelist 是同一真实文件。
  • 日志目标是 symlink 时，替换 symlink 节点，不修改 target。

如何读错误

解析、条件、环境变量和路径错误都展示完整 source chain。 错误包含原始条目、解析结果、行号和可行修复建议。

可预期的 filelist 失败由 CLI 以 FATAL 报告并返回退出码 1， 不暴露 Python traceback；未预期的工具内部失败返回 3。 

FATAL source file does not exist: /proj/rtl/missing.sv
source chain:
  /proj/tb/top.f:8
  /proj/tb/blocks/core.f:12
suggestion: check the path or define the macro that selects another branch
  1. 先看退出码：1 是输入问题，2 是参数问题，3 才是工具内部问题。
  2. 沿 source chain 从顶层 filelist 走到出错行，不要只看最后一个路径。
  3. 环境变量错误再检查 expansion chain，确认每一层都存在且非空。
  4. 需要观察读取和解析步骤时，重跑 --debug -l 并保留日志。
  5. 确认输出和日志没有与任一输入 filelist 指向同一真实文件。
